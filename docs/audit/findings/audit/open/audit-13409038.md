# No workflow is a required status check: main's protection requires an empty check list

## Problem

Class: non-gating-check (Verified). tests.yml (jobs "Bats (ubuntu-latest)", "Bats (macos-latest)", "Lint (yarn lint)", "Fish syntax and formatting"), linters.yml ("PR Lint") and semantic-pr.yml ("Semantic PR") all run on pull_request against main and look like merge gates. Branch protection on main enables required_status_checks with strict: true, but `checks` and `contexts` are both empty, and there are no rulesets. A PR with every one of these jobs red can be merged.

## Evidence

`gh api repos/ivuorinen/dotfiles/branches/main/protection` -> `"required_status_checks":{"strict":true,"contexts":[],"checks":[]}`; `enforce_admins: false`; no required_pull_request_reviews. `gh api repos/ivuorinen/dotfiles/rulesets` -> `[]`. `gh pr list --state merged -L 5`: 4 of the last 5 PRs were authored and merged by app/renovate (automerge). tests.yml:5-9 triggers on `pull_request: branches: [main]`.

## Impact

The "strict" protection gives the impression of a gate that does not exist. Renovate's automerge does wait for its own branch status by default, but that is a client-side Renovate setting (one `ignoreTests` in the shared ivuorinen/renovate-config turns it off), and any manually merged PR skips the gate entirely. Version bumps to tools that run on the owner's machines (mise pins) can land on a red Tests run.

## Fix

Add the job check names as required checks (the user runs this; it is not auto-applied):
```
gh api -X PATCH repos/ivuorinen/dotfiles/branches/main/protection/required_status_checks \
  -F strict=true \
  -f 'contexts[]=Bats (ubuntu-latest)' -f 'contexts[]=Bats (macos-latest)' \
  -f 'contexts[]=Lint (yarn lint)' -f 'contexts[]=Fish syntax and formatting' \
  -f 'contexts[]=PR Lint' -f 'contexts[]=Semantic PR'
```
Verify with `gh api repos/ivuorinen/dotfiles/branches/main/protection --jq '.required_status_checks.contexts'`. Do not require path-filtered workflows (copilot-setup-steps), because a required check that never reports blocks merges.
